KASETTI — Initial Requirements

1. Patient Verification

The system should allow a patient to scan a KASETTI QR code and access verification information associated with a doctor.

2. Doctor Identity

The system should display relevant doctor information in a clear and easy-to-understand format.

3. Registration Verification

Where technically and legally possible, the system should use trusted/authoritative medical-registration information to support verification.

4. QR Code

Each participating doctor should have a unique QR code that can be scanned using a smartphone.

5. User Experience

The verification process should be:

- Simple
- Fast
- Mobile-friendly
- Easy for non-technical users

6. Data Protection

The system should follow applicable privacy, security and healthcare-data requirements.

7. Administration

An authorized administrator should be able to manage participating doctors and their verification information.

8. Future Enhancements

Potential future features may include:

- Doctor profile verification
- Registration-status checking
- Hospital/clinic verification
- QR code generation
- Verification history
- Multilingual support
- Reporting of suspicious or invalid information

9. MVP

The first MVP should focus on one core workflow:

Doctor → KASETTI QR Code → Patient Scan → Trusted Verification Information

10. Project Status

These requirements are preliminary and will be refined after stakeholder discussions and technical feasibility assessment.
